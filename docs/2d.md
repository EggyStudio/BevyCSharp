# 2D

Sprites, cameras that look flat at the world, and the rest of drawing in two dimensions.

A 2D camera measures in pixels from the middle of the window, and sprites are entities under it:

```csharp
Render2d.SpawnCamera2d();

var badge = ctx.Ecs.Spawn();
Render2d.SetSprite(ctx.Ecs, badge, AssetServer.Load(AssetKind.Image, "ui/badge.png"));
ctx.Ecs.Add(badge, Transform.At(120f, -80f, 0f));
```

A sprite is a picture in the world rather than on the screen. It carries a `Transform` like
anything else, so parenting, hierarchy and every other component work on it. For something pinned
to the screen regardless of the camera, use `Ui` instead.

`SpriteSettings` tints, resizes, mirrors, and picks one rectangle out of a sheet, which is how a
single image holds many frames:

<!-- compiled with:
Entity badge = default;
AssetHandle sheet = default;
bool facingLeft = false;
-->
```csharp
Render2d.SetSprite(ctx.Ecs, badge, sheet, new SpriteSettings
{
    Rect = (0f, 0f, 32f, 32f),
    FlipX = facingLeft,
});
```

An atlas layout does the same counting for you. It is a list of rectangles over a grid of equal
tiles, so a frame is named by number rather than by arithmetic, and stepping an animation is
adding one:

<!-- compiled with:
Entity walker = default;
AssetHandle sheet = default;
uint step = 0;
-->
```csharp
var frames = Render2d.CreateAtlas(32, 32, columns: 8, rows: 1);

Render2d.SetSprite(ctx.Ecs, walker, sheet, new SpriteSettings
{
    Atlas = frames,
    Frame = step % 8,
    Anchor = SpriteAnchor.BottomCenter,
});
```

The layout takes no image, because it describes a cut rather than a picture, so one layout serves
every sheet cut the same way. `Anchor` moves the transform off the middle of the sprite, for
anything standing on the ground, and `SpriteAnchor` names the nine usual points. `Mode` decides how
the picture meets `Size`: `Sliced` keeps the corners and stretches the middle, so one small image
draws a panel at any size, `Tiled` repeats it instead, and `Scaled` keeps the picture's proportions
and letterboxes what is left over, with `Scaling` saying whether it is fitted inside the size or
made to fill it and which edges are kept.

`SliceTiling` says which parts of a sliced picture repeat rather than stretch. Stretching is wrong
for anything with a pattern in it, since a border of dots drawn twice as wide becomes a border of
ovals, and `SliceTiling.Sides`, `.Center` or `.All` keep a drawn edge looking drawn at every size.
The repeat is measured by `TileStretch`, the same number a whole tiled picture uses.

`Render2d.SpawnCamera2d(order: 1)` or any order above zero makes an overlay, which is how a 2D layer
sits on a 3D game. An overlay is more than a second camera with a higher order, since a camera draws
into a view of its own and then writes that over the target, so the bridge clears the overlay's own
view to nothing each frame and blends the result rather than overwriting. Left to itself a second
camera replaces the scene under it, which reads as the scene having failed to draw.

A flat shape is a mesh, drawn by a 2D camera with a material of Bevy's `ColorMaterial`. The mesh
is any `Render.CreateMesh` makes, with the flat shapes lying in the plane the camera looks at, and
`Render2d.SetMesh` and `Render2d.SetMaterial` put the two on an entity:

```csharp
var coin = ctx.Ecs.Spawn();
ctx.Ecs.Add(coin, Transform.At(0f, 40f, 0f));
Render2d.SetMesh(ctx.Ecs, coin, Render.CreateMesh(MeshShape.RegularPolygon, 24f, 8f));
Render2d.SetMaterial(ctx.Ecs, coin, Render2d.CreateMaterial(new ColorMaterialSettings
{
    Color = (1f, 0.8f, 0.2f, 1f),
}));
```

A material is an asset, shared by every mesh drawn with it, and `Render2d.WriteMaterial` changes it
in place for all of them at once. Its `Texture` is an image the color multiplies, its `AlphaMode`
draws every pixel solid, cuts the transparent ones out, or blends them with what is behind, and
`UvScale`, `UvRotation` and `UvOffset` move the image across the mesh. A scale above one repeats it,
which needs an image loaded with `TextureWrap.Repeat`, since one sampled as Bevy samples by default
stretches its last pixels instead.

`MeshShape.Ring(MeshShape.Circle)`, or the ring of any other flat shape with an inside, is the band
along the inside of that shape's outline, sized by the shape's measures and a third number for how
wide the band is. A sector or a segment is mapped onto its image as a mask over the circle it is cut
from, and `MeshShape.UvAngle(MeshShape.CircularSector)` takes a third number, the angle in radians
the mesh is mapped at, so a slice turned by its transform shows its image upright when the angle is
the same turn. A segment or a line through points is a mesh of lines, built from a `MeshData`
with its `Topology` set to `Lines` or `LineStrip`, and a `MeshData` with `Colors` gives each vertex
a color the material multiplies too. Bevy's `Wireframe2d` component, put on through its wrapper,
draws a mesh's edges over it in an app made with `Config.Wireframes`, which adds Bevy's wireframe
plugins and is off by default, since they look at every mesh every frame.

A tilemap chunk is a grid of tiles drawn as one mesh, in one call however many tiles it holds,
from the layers of one image loaded as an array, a tile to a layer. Each tile names its layer and
may be tinted, hidden, turned and mirrored, and a cell may hold nothing:

<!-- compiled with:
Entity entity = default;
-->
```csharp
var chunk = new TilemapChunk
{
    Width = 64, Height = 64, TileWidth = 8, TileHeight = 8,
    Tileset = AssetServer.LoadImage("textures/array_texture.png", new TextureSettings { Layers = 4 }),
};
var tiles = new TileData?[chunk.Count];                    // row after row from the bottom up
tiles[chunk.IndexOf(3, 4)] = TileData.FromTilesetIndex(2);
Render2d.SetTilemap(ctx.Ecs, ctx.Ecs.Spawn(), chunk, tiles);

Render2d.SetTiles(ctx.Ecs, entity, chunk.IndexOf(0, 0), [null]);   // a cell emptied afterwards
```

The chunk is centered on its entity, and `chunk.TileTransform(x, y)` is where a tile's middle sits,
for something that stands on a tile. Bevy's `TilemapChunk` is made from its tiles as it is put on,
so a run that draws nothing, headless, refuses one.

Meshes are layered by depth, as sprites are, so the one nearer the camera on the Z axis covers the
other. The blended ones are drawn after the solid ones and back to front, so each shows whatever is
behind it. Two at the same depth draw in an order nothing promises, which may differ between frames
and between versions of Bevy, so one meant above another is given a greater Z.

Stepping a sprite through the frames of a sheet needs no engine support, since `Frame` names a
frame by number. `SpriteAnimation` in `BevyCSharp.FeatureTest` is the whole of it, a timer and a
counter, and it is there to be copied rather than shipped in the library, where it would be the
wrong shape for any game wanting frame events or a queue of clips.

Many sprites turning at once are moved together. `Render2d.SetSpriteFrames` takes the sprites and
the frame each moves to, writes only the index of each one's sheet, and crosses into the bridge
once, where setting each sprite again would cross once a sprite and replace it whole. It moves a
sprite mesh the same way.
